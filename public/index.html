ACID Principles & Concurrency Control Strategy

Atomicity

"All or Nothing." If payment fails at Step 7, all earlier operations (Order creation, inventory decrement) are discarded via rollback.

Consistency

Database moves from one valid state to another. Constraints such as CHECK (quantity_available >= 0) are strictly enforced.

Isolation

Serializable & Repeatable Read isolation levels with row locks (FOR UPDATE) prevent Dirty Reads and Lost Updates.

Durability

Committed transactions are permanently logged to non-volatile storage (WAL) and survive application crashes.

Cache-Aside (Lazy Loading) Implementation Pattern

  1. Step 1 (Read Request): Application first queries Redis cache using key (e.g. cache:products:all).
  2. Step 2 (Cache Hit): If key exists and TTL is valid, returns data in < 2ms without touching database.
  3. Step 3 (Cache Miss): If key is absent or expired, queries relational database (PostgreSQL/MySQL), stores the result in Redis with a TTL (Time-To-Live), and returns data to user.
  4. Step 4 (Mutation Invalidation): Whenever an INSERT, UPDATE, or DELETE occurs in the database, the corresponding cache key is immediately invalidated to prevent stale data.

Cost-Effective Student Tier Strategy

For college academic demonstrations, using expensive enterprise cloud tiers is counterproductive. This project utilizes AWS Free Tier (750 hours/month of EC2/RDS t4g.micro, 5GB of S3 standard storage), combined with MongoDB Atlas M0 Free Cluster and Neo4j AuraDB Free Tier, achieving $0.00/month operational expense while demonstrating 100% genuine cloud database architecture.
